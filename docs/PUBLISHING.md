# Git 与开源发布

公共目录只保留通用教程、代码、无真实值示例和测试。`private/`、`.tmp/`、`.env`、密钥及运行日志不上传。公共文档使用仓库相对链接，不写任何人的绝对工作区路径。许可证是 MIT，第三方程序不随仓库分发。

## 提交前

先更新受影响文档和公共 ROADMAP，用户实例状态另写私有记录。按授权执行：

```sh
python3 -m unittest discover -s tests -v
python3 scripts/check-public.py
```

扫描器检查未忽略的公共文件、暂存内容和可达 Git 历史，检测私钥、节点 URI、部分常见 Token 模式、个人绝对路径及当前本地环境提供的已知身份／凭据。它不能保证发现所有未知秘密，仍需人工或 AI 审查文件清单和内容。

环境配置位于忽略目录，`.gitignore` 不保护已跟踪文件；扫描器也会检查被误跟踪的私有路径。发现问题先停止提交或发布，保留私有原件并从公共材料去除。若凭据曾进入远端历史，应先处理泄漏与轮换，再按专项授权处理历史，不假设删除最新文件就消除了泄漏。

仅暂存明确的公共文件和目录，不使用 `git add -f`。暂存后再次运行扫描并检查：

```sh
python3 scripts/check-public.py
git diff --cached --check
git diff --cached --stat
```

检查后使用中文提交信息，不加协作者署名。提交和推送都需要用户授权；授权范围明确时无需重复确认。

## GitHub 发布

发布前核对登录账号、目标仓库所有者／名称、public 可见性和许可证。优先使用现有 GitHub CLI；无有效登录时让人在自己的终端运行 `gh auth login`，不让人把 Token 发给 AI。登录、网络沙箱和令牌失效是不同问题，先核对错误再处理。

已有远端时先只读检查，不覆盖同名仓库和已有历史。新仓库只有在明确授权且同名仓库不存在时创建。推送前对即将发布的提交及所有可达历史执行扫描，提交作者邮箱也要核对：使用用户认可的公开身份或 GitHub 提供的 noreply 邮箱，不擅自公开本地私人邮箱，不修改全局 Git 身份。

远端查询确认为 public 且已包含目标提交后，才能报告“已开源发布”；只有本地 commit 就报告本地完成。可下载公开仓库再次核对文件清单，确保没有私有目录或个人资料。
